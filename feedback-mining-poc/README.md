# Feedback Mining POC — TypeSafe Jev via OpenRouter

A proof-of-concept for TypeSafe's **"map-reduce over big data"** use case
(from `typesafe.ai/blog/introducing-system-one-models-and-jev`: "turn
petabytes of data into features and insights"). It mines a batch of product
reviews, extracting structured features per review with Jev (the **map**),
then aggregates those features into a dashboard-style report with plain code
(the **reduce** — no model call involved).

Unlike `code-review-poc/` (one verdict per item) or `email-classification-poc/`
(one label per item), this POC's actual output is a **batch-level report**:
sentiment trends, topic breakdown, and an escalation list — the point of
map-reduce is the aggregate insight, not any single item's answer.

## Dataset

`reviews/reviews.json`, generated by `generate_reviews.py` from 10 randomized
SaaS-product review templates (pricing complaints, billing overcharges,
performance praise, bug reports, feature requests, integration issues, etc.),
each filled in with `Faker` data so every review is unique.

```bash
python generate_reviews.py --items 300 --seed 42
```

This **wipes and rebuilds** `reviews/reviews.json`. `--seed` makes it
reproducible.

## How it mines (map step)

One call per review, four parallel questions over
`state = {"review_text", "rating_stars"}`:

- `sentiment` (**Score**, 5 levels: very negative → very positive)
- `topic` (**Choice**: pricing / performance / usability / customer_support /
  reliability_bugs / feature_request / integrations / other)
- `actionable_feedback` (**Noul**: concrete bug report or feature request?)
- `urgency` (**Score**, 4 levels: none → minor → significant pain point →
  severe/blocking)

All reviews are mined concurrently (`ThreadPoolExecutor`, 40 workers, progress
every 50) against a shared, connection-pooled `requests.Session` with
automatic retries on transient errors (429/500/502/503/504) — 300 reviews
mine in a few seconds. A failure that survives the retries is still caught
and reported rather than aborting the batch.

## How it reports (reduce step — pure code, no model calls)

- Sentiment distribution + overall average.
- Topic breakdown: count, % of total, average sentiment per topic.
- Actionable-feedback rate, overall and per topic.
- **Escalation list**: reviews with `urgency >= 2` at confidence `>= 0.5`
  (a high-urgency call at low confidence is labeled `NEEDS_HUMAN_REVIEW`
  instead of being trusted outright, per TypeSafe's
  [confidence guidance](https://docs.typesafe.ai/confidence)).
- A few derived insight lines (e.g. "'pricing' has the lowest average
  sentiment") computed purely from the aggregates above — the model never
  writes these sentences, code does.

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env
# edit .env and set OPENROUTER_API_KEY
```

## Run

```bash
python generate_reviews.py       # build/rebuild the dataset (defaults: 300, seed 42)
python mine_feedback.py          # map + reduce, prints the dashboard report
python mine_feedback.py --verbose  # also prints the full escalation list (not just top 15)
```

## Notes

- `jev_client.py` here is an exact copy of the adapter verified live in the
  other two POCs, hitting OpenRouter's `POST /api/alpha/decisions` endpoint
  (the standard `chat/completions` endpoint rejects this model outright).
- The generator stores which template produced each review internally, purely
  so you can sanity-check the report (e.g. confirm the escalation list is
  dominated by the intentionally severe `billing_overcharge_urgent` template)
  — that field is never sent to Jev as part of the mining state.
